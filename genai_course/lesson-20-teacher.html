תוצר: WEB APP BLUEPRINT + STATIC PROTOTYPE · עיקרון: USER → INPUT → LOGIC → OUTPUT

🏠 הקורס👨‍🏫 מורה🧑‍🎨 תלמיד

🎯 מה באמת לומדים היום?

היום עוברים מ־Website שמציג תוכן ל־Web App שמקבל משהו מהמשתמש ומחזיר תוצאה. המיומנות היא לחשוב על מוצר אינטראקטיבי לפני שמעצבים או כותבים קוד.

USER
מי משתמש?
INPUT
מה המשתמש נותן/בוחר?
LOGIC
מה האפליקציה אמורה לעשות עם זה?
OUTPUT
מה המשתמש מקבל בחזרה?

בסוף: התלמיד יוכל להסביר את האפליקציה שלו במשפט, למפות USER→INPUT→LOGIC→OUTPUT ולבנות STATIC PROTOTYPE שממחיש את הזרימה בלי צורך בקוד עובד עדיין.

🚀 מהאתר החי לאפליקציה

מה באמת לומדים? אתר יכול להגיב חזותית; Web App גם מקבל קלט, מפעיל כלל ומחזיר תוצאה. המודל: USER → INPUT → LOGIC → OUTPUT.

📦 כבר קיים: FINAL WORLD WEBSITE עם UI Motion/Feedback. 🎨 היום ב־Canva: בונים WEB APP BLUEPRINT וגם STATIC PROTOTYPE אמיתי של SKYLAND CLOUDPACK BUILDER — מסכים שאפשר להראות ולדמות בהם את המסלול, גם אם הלוגיקה עדיין לא פועלת.

✅ בסוף: Blueprint + Static Prototype. ➡️ במפגש 21: הופכים אותו למערכת מסכי UI מלאה.

🎬 Tutorial למדריך — CLOUDPACK BUILDER V0

  1. הציגו את האתר ממפגש 19 ושאלו: “הוא מגיב יפה — אבל האם הוא יכול לבחור תוצאה לפי מה שהמשתמש בחר?”
  2. כתבו על המסך: USER → INPUT → LOGIC → OUTPUT.
  3. הגדירו דוגמה: המשתמש בוחר Weather ו־Mission; האפליקציה תחזיר Cloudpack/Mission מתאים.
  4. ב־Canva בנו בפועל Prototype סטטי: Welcome → Input/Selection → Result.
  5. הדגימו “כאילו לחצנו”: עברו ידנית למסך התוצאה. הסבירו: זה עדיין Prototype — אין Logic פעיל.
  6. שאלו מה חסר כדי שהמחשב יעשה את המעבר בעצמו. שמרו את התשובה למפגשים 22–23.

🔗 מה כבר קיים ומה מתחיל היום?

יחידה 4 הסתיימה עם FINAL WORLD WEBSITE. עכשיו מתחיל פרויקט Web App אחד מתמשך: Blueprint → UI → Logic → Canva Code/Prototype → QA → Launch. מפגש 20 הוא נקודת ההתחלה של האפליקציה, והתוצר שלו הוא חומר הגלם למפגש 21.

☁️ דוגמה מוכנה — SKYLAND CLOUDPACK BUILDER

USER: מבקר בעולם SKYLAND שרוצה Cloudpack שמתאים למשימה שלו.
INPUT: Mission + Priority.
LOGIC: האפליקציה משווה את הבחירות לכללי התאמה.
OUTPUT: Cloudpack Result.

דוגמת זרימה: “בחר Mission” → “בחר Priority” → [האפליקציה מחליטה] → “זה ה־Cloudpack שמתאים לך”.

🟢 בדיקת Canva Education + הכנה

🟢 Design, Text, Shapes, Pages. 🟡/🔄 Canva Code / Canva AI לפי זמינות והרשאות. 🔄 Interactive Prototype באמצעות Pages/Links/Presentation. במפגש 20 לא נדרש קוד עובד.

הכן CLOUDPACK BUILDER, גרסת Blueprint + Static Prototype טובה וגרסה מבלבלת להשוואה. בדוק מראש את חשבון התלמיד. אין פרסום ציבורי כתנאי.

✨ פתיחת WOW + המשימה

הצג שני מסכים: Website שמספר על CLOUDPACK לעומת Builder שבו המשתמש בוחר Mission/Priority ומקבל Result. שאל: “מה ההבדל בין משהו שאני רק קורא לבין משהו שמגיב למה שאני עושה?”

Mission מהמקור: לבנות WEB APP BLUEPRINT + STATIC PROTOTYPE, לבדוק מול אדם/קריטריון ולשפר לפחות דבר אחד.

🖥️ הדגמת המדריך — Tutorial ייעודי

1. מתחילים ב־USER, לא במסך

כתוב: “SKYLAND visitor preparing for a mission”. שאל: “מה הוא צריך להשיג בעזרת האפליקציה?”

2. INPUT

צור ב־Canva עמוד Blueprint והוסף שני אזורי בחירה: Mission ו־Priority. הסבר: אלה הדברים שהמשתמש נותן למערכת.

3. LOGIC

במרכז ה־Blueprint כתוב כלל פשוט: “אם Mission/Priority = X → הצג Cloudpack מתאים”. היום לא מקודדים אותו; מגדירים מה המערכת אמורה לעשות.

4. OUTPUT

צור מסך Result עם שם Cloudpack, תמונה/Placeholder ומשפט קצר המסביר למה התקבלה התוצאה.

5. בונים STATIC PROTOTYPE

צור מסך פתיחה → מסך בחירה → מסך Result. Shapes/Buttons מראים מה המשתמש אמור ללחוץ, גם אם עדיין אין לוגיקה אמיתית.

6. הטעות המכוונת

הצג Prototype עם הרבה כפתורים אך בלי Input ברור, או Result שלא קשור לבחירה. שאל: “מה נתן המשתמש? מה האפליקציה החזירה? האם אפשר להסביר את הקשר?”

7. בדיקת Flow

תן לתלמיד אחר להצביע על המסכים ולספר: USER → INPUT → LOGIC → OUTPUT. אם הוא לא יכול, ה־Blueprint עדיין לא ברור.

מה נשאר על המסך?

Blueprint עם ארבעת החלקים + Static Prototype של הזרימה. לא מוצר מקודד.

🏆 Boss + User Test

התלמיד נותן לחבר את ה־Static Prototype בלי להסביר. החבר צריך לזהות מי המשתמש, מה הוא בוחר ומה אמור לקרות בסוף. התלמיד משנה דבר אחד בעקבות הבדיקה.

Super Boss מהמקור: הסר רכיב לא חיוני. אם ה־Blueprint + Prototype עדיין עובדים, הסבר מדוע הוא Nice to Have ולא Must Have.

מפגש 23: בונים את האפליקציה שלי עם Canva Code

תוצר: WORKING WEB APP V1 · עיקרון: SPEC → BUILD → TEST → CHANGE → TEST AGAIN

מה באמת לומדים היום?

להפוך תכנון UI + Decision Tree ל־מפרט התנהגות ברור שמערכת יכולה לבנות ולבדוק. התלמיד לא לומד תחביר JavaScript; הוא לומד לתאר לוגיקה בצורה חד־משמעית.

עיקרון חשוב: התלמידים לא כותבים JavaScript; הם מתכננים לוגיקה ומנסחים Spec/Prompt ברור.

🎯 המיומנות: SPEC → BUILD → TEST → CHANGE → TEST AGAIN.

📦 → 🎨 → ✅ → ➡️

📦 קיים: APP UI KIT + Decision Tree.
🎨 היום: בונים ב־Canva Code את WORKING WEB APP V1.
✅ בסוף: המשתמש יכול לבחור Input ולקבל Output מתאים.
➡️ הבא: מפגש 24 מנסה לשבור את אותה אפליקציה.

🎬 הדרכה למדריך — עץ החלטות → מפרט → אפליקציה עובדת

  1. פתחו את ארבעת מסכי ה־UI ואת Decision Tree של SKYLAND MISSION CONTROL.
  2. אמרו: “אנחנו לא מבקשים ‘תבנה אפליקציה מגניבה’. אנחנו נותנים מפרט שאפשר לבדוק.”
  3. בנו Spec טבעי: Inputs: Weather=STORM/CALM; Mission=RESCUE/EXPLORE. Rule: כל שילוב מחזיר Output מוגדר.
  4. הוסיפו את ארבעת ה־Outputs מהעץ. בקשו לשמור על שפת ה־UI של SKYLAND.
  5. הפעילו Canva Code ובנו V1. אין צורך להציג או לכתוב JavaScript.
  6. בדקו ארבעה שילובים אחד־אחד. סמנו PASS/FAIL.
  7. שנו דבר אחד בלבד ב־Spec/Prompt בעקבות Fail, בנו/עדכנו ובדקו שוב.
☁️ Spec לדוגמה — scaffolding:
Build an interactive SKYLAND Mission Control. Let the user choose Weather: STORM or CALM, then Mission: RESCUE or EXPLORE. Return exactly one result: STORM+RESCUE→STORM RESCUE; STORM+EXPLORE→LIGHTNING MYSTERY; CALM+RESCUE→SKY DELIVERY; CALM+EXPLORE→SECRET ISLAND. Keep the interface simple and consistent with the prepared SKYLAND UI.

🏆 אתגר הבוס — משנים דבר אחד בלי לשבור משהו אחר

שנו דבר אחד באפליקציה, ואז בדקו מחדש גם מסלולים שלא שיניתם. המטרה: שיפור בלי לשבור משהו שכבר עבד.

🆘 ערכת הצלה למדריך

🟡 Canva Code חסום: השתמשו ב־Interactive Prototype עם Pages/Links והדגימו את אותה לוגיקה ידנית. יעד הלמידה נשאר Spec + Test. אם התוצאה לא נכונה, אל תוסיפו עוד ועוד בקשות — חזרו ל־Decision Tree ותקנו כלל אחד.

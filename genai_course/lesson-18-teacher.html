🎯 מה באמת לומדים היום?

המיומנות היא UX Navigation: לעצב את הדרך שבה מבקר מתמצא ופועל באתר. אתר יכול להיות יפה ומלא תוכן ועדיין להיכשל אם המשתמש לא יודע איפה הוא, לאן ללכת או מה יקרה בלחיצה.

WHERE AM I?
האם ברור באיזה Section אני?
WHERE CAN I GO?
מה האפשרויות הבאות?
WHAT HAPPENS IF I CLICK?
האם הפעולה הצפויה ברורה?

בסוף: התלמיד יוכל לבנות ולבדוק מסלול משתמש בתוך One-Page ולהסביר החלטת ניווט אחת ששיפר בעקבות בדיקה.

✨ חשוב — תנועת ממשק בלי כתיבת קוד

המיומנות: התלמיד לומד לחשוב על התנהגות הממשק, לא לכתוב :hover, transform או transition.

מודל החשיבה: TRIGGER → MOTION → FEEDBACK → PURPOSE. קודם מחליטים מה המשתמש עושה, אחר כך מה משתנה על המסך, איזה Feedback הוא מקבל ולמה זה עוזר לו.

תוצר Canva של היום: באותו One-Page, התלמיד מתכנן ומיישם לפחות 3 Micro-interactions/אנימציות UI מתאימות לכלים הזמינים: למשל Button Feedback, Card Emphasis, Reveal/Entrance או מעבר שמכוון את העין. אין דרישה לכתיבת CSS או JavaScript.

☁️ SKYLAND — דוגמה מוכנה:
1. EXPLORE button — המשתמש מזהה שזה רכיב לחיץ → Feedback חזותי ברור.
2. CLOUDPACK card — הדגשה עדינה שמושכת תשומת לב למוצר.
3. CTA section — כניסה/הדגשה שמובילה לפעולה.
שאלת המדריך: “האם התנועה עוזרת למשתמש להבין מה לעשות — או שהיא רק קישוט?”

🎬 הדרכה למדריך — תנועה לפני לוגיקה

  1. פתחו את אותו Canva Website ממפגש 17 ועברו ל־Preview.
  2. הצביעו על רכיב אינטראקטיבי ושאלו: “מה המשתמש מצפה שיקרה כאן?”
  3. בחרו רכיב אחד והגדירו יחד: TRIGGER → MOTION → FEEDBACK → PURPOSE.
  4. יישמו אפקט/אנימציה זמינים בממשק Canva בלי להראות או לכתוב קוד.
  5. הדגימו בכוונה אנימציה חזקה/מיותרת ושאלו: “מה היא עוזרת להבין?” אם אין תשובה — מפחיתים או מסירים.
  6. עברו שוב ל־Preview ובדקו: האם ברור יותר מה לחיץ, מה חשוב ולאן ממשיכים?
  7. חזרו על התהליך לעוד שני רכיבים.

מה נשאר על המסך בסיום: אותו One-Page V2 עם Navigation + לפחות 3 החלטות Motion/Micro-interaction שניתן להסביר את מטרתן.

✨ פתיחת WOW + המשימה

הצג את אותו SKYLAND בשתי גרסאות: אחת שבה ברור כיצד להתקדם ואחת עם ניווט מבלבל. שאל: “בלי שאני מסביר — לאן הייתם לוחצים עכשיו?”

Mission: לבנות INTERACTIVE WEBSITE V2, לבדוק אותו מול אדם/קריטריון ולשפר לפחות דבר אחד.

🖥️ הדגמת המדריך — הדרכה מעשית

0. פותחים את האתר הקיים

פתח את אותו SKYLAND One-Page ממפגש 17 ובצע Preview. אמור: “התוכן כבר כאן. היום לא בונים עוד אתר — מעצבים את הדרך בתוך האתר הזה.”

1. מפת המסע

כתוב: HOME → WORLD → LEO → STORY → CLOUDPACK → VIDEO. ליד כל שלב שאל: “איפה אני? לאן אני רוצה לעבור?”

2. ניווט

חזור ל־Canva Website. צור/הגדר Navigation לפי האפשרויות הזמינות בממשק. השתמש בשמות קצרים התואמים ל־Sections. כאשר אפשר, חבר פריט ליעד המתאים; אחרת השתמש במסלול prototype.

3. כפתור עם הבטחה ברורה

ב־Hero בחר CTA. במקום “לחצו כאן”, כתוב למשל “גלו את SKYLAND” וחבר אותו ליעד המתאים לפי הממשק הזמין. הסבר שהטקסט צריך לרמוז מה יקרה.

4. שלוש שאלות חוויית המשתמש

ב־Preview עצור ב־World ושאל: WHERE AM I? WHERE CAN I GO? WHAT HAPPENS IF I CLICK?

5. טעות מכוונת

שנה כפתור ל־“MORE”/“CLICK HERE” או חבר אותו ליעד לא צפוי. שאל: “מה ציפית שיקרה ומה קרה?”

6. מבחן מבקר שהלך לאיבוד

תן משימה: “מצא את CLOUDPACK בלי שאסביר איך.” שתוק וצפה. עצירה, חזרה או בחירה לא נכונה הן מידע UX.

7. תיקון

תקן דבר אחד בלבד — שם Navigation, מיקום, Button label או Link — וחזור על אותה משימה.

מה חייב להישאר בסיום?

אותו One-Page עם Navigation + Buttons/Links + כל ה־Sections הקיימים, ו־Preview שבו ניתן לבדוק את מסלול המשתמש.

🧪 מעבדת חוויית משתמש — בדיקת מסלול בפועל

מטרת הבדיקה: לא לשאול “האם האתר יפה?”, אלא לבדוק אם אדם אחר מצליח להשתמש בו בלי הסבר.

  1. BUILD: ודאו שה־Navigation וה־Buttons/Links נמצאים באותו One-Page.
  2. PREVIEW: פתחו את האתר ב־Preview והתחילו מה־Hero.
  3. USER TASK: תנו לבודק משימה אחת, למשל: “מצא מי הדמות הראשית ואז עבור למוצר שלה.”
  4. OBSERVE: היוצר שותק. מסמנים איפה המשתמש היסס, חזר אחורה או לחץ על משהו לא צפוי.
  5. FIND THE LOST MOMENT: מזהים את הרגע המדויק שבו המסלול הפסיק להיות ברור.
  6. FIX ONE THING: משנים דבר אחד בלבד — שם כפתור, מיקום, סדר, סימון Section או יעד Link.
  7. RETEST: חוזרים על אותה משימה ובודקים אם הבעיה נפתרה.

📱 בדיקת גלילה + מובייל

בצעו Scroll Test מתחילת ה־One-Page עד סופו. אם Preview בחשבון מציע תצוגת Mobile, בדקו גם אותה. המטרה נשארת זהה: האם המסלול ברור גם כשהאתר מוצג במסך צר?

🏆 אתגר הבוס — בדיקת UX ללא הסברים

זהו ה־Boss מהמקור. היוצר נותן משימה קצרה ואז לא מדבר. המשתמש צריך להסתדר באמצעות האתר בלבד. היוצר רושם איפה המשתמש ידע מה לעשות ואיפה נתקע.

Super Boss: הסר רכיב שאינו חיוני. אם INTERACTIVE WEBSITE V2 עדיין עובד, הסבר מדוע הוא Nice to Have ולא Must Have.

תוצר: APP UI KIT + SCREEN SYSTEM · עיקרון: HIERARCHY + CONSISTENCY + FEEDBACK

🏠 הקורס👨‍🏫 מורה🧑‍🎨 תלמיד

🎯 מה באמת לומדים היום?

היום לא “מקשטים אפליקציה”. לומדים UI Design: איך לגרום למשתמש להבין מה חשוב, לזהות רכיבים שחוזרים על עצמם ולקבל סימן ברור שהפעולה שלו נקלטה.

HIERARCHY
מה רואים ראשון, שני ושלישי?
CONSISTENCY
האם אותו סוג פעולה נראה ומתנהג באופן עקבי?
FEEDBACK
איך המשתמש יודע שבחר, התקדם או קיבל תוצאה?

בסוף: התלמיד יוכל לבנות מערכת מסכים עקבית ולהסביר החלטת UI אחת ששיפר בעקבות בדיקה.

🖥️ היום בונים את מסכי האפליקציה האמיתיים

המיומנות: HIERARCHY + CONSISTENCY + FEEDBACK. לא מסתפקים ברשימת עקרונות — בונים בפועל ב־Canva את APP UI KIT + SCREEN SYSTEM.

📦 כבר קיים: Blueprint + Static Prototype ממפגש 20. 🎨 היום: בונים 4 מסכים: 1 Welcome/Start → 2 Choose Weather → 3 Choose Mission → 4 Mission Result, כולל Default/Selected/Feedback states.

✅ בסוף: ארבעת המסכים קיימים ב־Canva באותה שפה חזותית. ➡️ מפגש 22: נחבר ביניהם באמצעות Decision Tree.

🎬 הדרכה למדריך — בונים ממשק ולא רק מדברים עליו

  1. פתחו את Prototype V0 והעתיקו את שפת המותג — צבעים, טיפוגרפיה וכפתורים.
  2. בנו Screen 1: WELCOME → START.
  3. בנו Screen 2: Choose Weather → STORM / CALM → CONTINUE.
  4. בנו Screen 3: Choose Mission → RESCUE / EXPLORE → GET MY MISSION.
  5. בנו Screen 4: MISSION RESULT.
  6. צרו מצב Selected לאחת הבחירות ושאלו: “איך המשתמש יודע שהבחירה נקלטה?”
  7. הדגימו בכוונה כפתורים בצבעים/גדלים לא עקביים; תקנו באמצעות HIERARCHY + CONSISTENCY + FEEDBACK.

🔗 ממשיכים מאותה אפליקציית Web

כבר קיים: WEB APP BLUEPRINT + STATIC PROTOTYPE ממפגש 20, כולל USER → INPUT → LOGIC → OUTPUT.

היום: לא משנים את רעיון האפליקציה ולא מתחילים פרויקט צדדי. הופכים את אותו Prototype ל־APP UI KIT + SCREEN SYSTEM. במפגש 22 נוסיף לאותה אפליקציה את הלוגיקה.

✨ פתיחת WOW + המשימה

הצג שני מסכי CLOUDPACK BUILDER עם אותו תוכן: אחד שבו כל כפתור נראה אחרת ואין Selected State, ואחד עם Hierarchy, Consistency ו־Feedback. שאל: “באיזה מסך ידעתם מיד מה לעשות — ואיך המסך גרם לכם לדעת?”

Mission: לבנות APP UI KIT + SCREEN SYSTEM, לבדוק מול אדם/קריטריון ולשפר לפחות דבר אחד.

🖥️ הדגמת המדריך — הדרכה מעשית

1. פותחים את אותו אב־טיפוס

פתח את CLOUDPACK BUILDER ממפגש 20. הצג את USER→INPUT→LOGIC→OUTPUT ואמור: “הפעולה כבר הוגדרה. היום אנחנו מלמדים את המסך להסביר אותה.”

2. היררכיה

במסך הבחירה סדר כותרת, הוראה, אפשרויות ו־CTA. הגדל/הדגש רק את מה שצריך להיקרא ראשון. שאל: “אם אני מסתכל 3 שניות — מה ראיתי ראשון?”

3. עקביות

בנה רכיב Option אחד: Shape, טקסט, מרווח ומיקום. שכפל אותו לאפשרויות האחרות במקום לעצב כל אפשרות מחדש. בנה גם כלל קבוע ל־Primary Button.

4. מצב נבחר = משוב

שכפל Option והראה מצב “נבחר”. אפשר להשתמש במסגרת/סימון/שינוי חזותי ברור. הסבר: המשתמש צריך לדעת שהמערכת קלטה את הבחירה.

5. התקדמות

הוסף סימון פשוט כמו 1/2 → 2/2 → Result. שאל: “איך המשתמש יודע כמה נשאר?”

6. תוצאה

במסך התוצאה תן ל־Cloudpack Result עדיפות חזותית ברורה, ואחריו הסבר קצר ופעולה הבאה.

7. טעות מכוונת

שנה Button אחד לצבע/צורה שונים ללא סיבה, הסר Selected State או הפוך טקסט משני לגדול מהפעולה הראשית. בקש לזהות איזה מעקרונות ה־UI נשבר.

8. בדיקת משתמש

תן לתלמיד לבחור אפשרות ולהצביע מה הוא מצפה שיקרה. היוצר שותק. רשום נקודת בלבול אחת ובצע שינוי אחד.

מה נשאר על המסך?

מסכי Start/Selection/Result עקביים + UI Kit קטן שמראה Primary Button, Option, Selected State, Progress וכללי טקסט בסיסיים.

🏆 אתגר הבוס — מבחן ממשק של 3 שניות

הצג מסך למשך כ־3 שניות. הבודק אומר מה ראה ראשון ומה הוא חושב שצריך לעשות. אם התשובה אינה תואמת למטרה — מתקנים Hierarchy.

Super Boss מהמקור: הסר רכיב לא חיוני. אם APP UI KIT + SCREEN SYSTEM עדיין עובד, הסבר למה הוא Nice to Have ולא Must Have.

🎬 Tutorial למדריך — Decision Tree חזותי

  1. בנו ב־Canva: START → WEATHER?
  2. פצלו ל־STORM / CALM.
  3. מתחת לכל ענף הוסיפו MISSION? → RESCUE / EXPLORE.
  4. חברו כל שילוב ל־Output המתאים.
  5. שתלו בכוונה Bug: STORM + RESCUE → SECRET ISLAND.
  6. בקשו מהכיתה “להריץ” את העץ באצבע ולמצוא את הטעות.
  7. תקנו ושמרו את העץ לצד מסכי ה־UI; זה חומר הגלם הישיר ל־Canva Code.

☁️ דוגמת SKYLAND — כלל מוכן

IF mission = RESCUE AND priority = SAFETY THEN RESCUE PACK

Variables: mission, priority · Conditions: mission=RESCUE? priority=SAFETY? · Rule: אם שניהם נכונים → Decision: RESCUE PACK.

🟢 Design, Text, Shapes, Pages. 🟡 Canva Code / Canva AI לפי הרשאות. 🔄 Decision Tree ו־Interactive Prototype ב־Pages/Links/Presentation. מטרת השיעור אינה תלויה בזמינות Canva Code.

הכן מראש את דוגמת SKYLAND, Decision Tree תקין וגרסה אחת עם Rule שגוי. בדוק בחשבון תלמיד אמיתי. לפי המקור, הכשרת המדריך המומלצת כוללת Get to Know Canva Code, AI Essentials ו־Engaging Students with Canva.

הצג שתי בחירות: Mission=RESCUE ו־Priority=SAFETY. שאל: “איך האפליקציה יודעת איזה Cloudpack להחזיר?”

Mission מהמקור: לבנות APP LOGIC BLUEPRINT + DECISION TREE, לבדוק מול אדם/קריטריון ולשפר לפחות דבר אחד.

🖥️ הדגמת המדריך — Logic Tutorial מעשי

1. פותחים את ה־UI הקיים

פתח את CLOUDPACK BUILDER ממפגש 21 והצבע על Mission ו־Priority. אמור: “אלה כבר לא רק כפתורים. הערכים שלהם הם מידע שהלוגיקה צריכה לקרוא.”

2. מגדירים VARIABLES

ב־Canva צור אזור Blueprint עם שני Shapes: mission ו־priority. מתחת לכל אחד כתוב דוגמאות לערכים אפשריים.

3. בונים CONDITION ראשון

צור Diamond/Shape של שאלה: mission = RESCUE?. חבר YES ו־NO לשני נתיבים. הסבר: Condition הוא משהו שאפשר לענות עליו כן/לא.

4. מוסיפים CONDITION שני

בנתיב YES הוסף: priority = SAFETY?. עכשיו אפשר לראות שהחלטה יכולה להיות תלויה ביותר מתנאי אחד.

5. כותבים RULE

לצד העץ כתוב במפורש: IF mission=RESCUE AND priority=SAFETY THEN RESCUE PACK.

6. מחברים DECISION/OUTPUT

בסוף הנתיב הנכון הוסף Result: RESCUE PACK. חבר את הנתיבים האחרים לתוצאות/Placeholder המתאימות לתכנון התלמיד.

7. טעות מכוונת

שנה בכוונה את ה־Rule כך ש־RESCUE+SAFETY יוביל ל־Pack לא מתאים. תן לכיתה Test Case ושאל: “איפה בדיוק העץ קיבל החלטה לא נכונה?”

8. TEST CASES

הרץ לפחות שני סטים של Inputs על העץ. בכל צומת עצור ושאל YES/NO עד שמגיעים ל־Output. תקן Rule אחד ובדוק שוב.

מה נשאר על המסך?

Variables ברורים + Rules כתובים + Decision Tree שמתחיל ב־Input ומסתיים ב־Output, מוכן לתרגום ל־Spec/Canva Code במפגש 23.

⏱️ שלבי העבודה מהמקור

38–53 Rules · 53–63 Decision Tree · 63–72 Test Cases · 72–80 Boss · 80–90 Save. אם הכיתה מתעכבת, מקצרים קישוטים — לא Test Cases, Save והחיבור למפגש הבא.

🏆 Boss — EDGE CASE

תנו לעץ צירוף Inputs שלא בדקתם קודם. האם יש לו נתיב ברור עד Output? אם הוא “נתקע”, חסר Condition/Rule. הוסיפו רק את מה שנדרש כדי לסגור את המקרה.

Super Boss: נסו להסיר Rule/Branch שאינו חיוני. אם המערכת עדיין מקבלת את כל ההחלטות הנדרשות, הסבירו מדוע הוא היה Nice to Have.
